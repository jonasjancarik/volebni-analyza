# Data Directory Structure

This document explains the reorganized data directory structure that separates input and output data for better organization and clarity.

## Directory Structure

```
volebni-analyza/
├── input/                     # All input data (source files)
│   └── raw/                   # Raw source data files
│       ├── *.xml              # Electoral district XML files
│       ├── *.csv              # Election results CSV files  
│       └── ...                # Other raw data sources
│
├── output/                    # All generated/processed data
│   ├── processed/             # Processed and cleaned data
│   │   ├── prague5_municipal_*.json
│   │   └── prague5_comprehensive.json
│   ├── detailed/              # Detailed analysis data
│   │   └── prague5_electoral_districts.json
│   ├── results/               # Final analysis results
│   │   ├── analysis_summary.json
│   │   └── prague5_comprehensive_results.json
│   ├── visualizations/        # Generated charts and maps
│   │   ├── index.html
│   │   ├── turnout_analysis.html
│   │   └── districts_map.html
│   └── reports/               # Analysis reports
│       ├── comprehensive_analysis_report.json
│       └── analysis_summary.md
│
└── data/                      # (Legacy - to be removed)
    ├── raw/
    ├── processed/
    ├── detailed/
    └── results/
```

## Directory Purposes

### Input Directory (`input/`)
Contains all source data that feeds into the analysis pipeline:

- **`input/raw/`**: Original, unmodified data files
  - XML files with electoral district information
  - CSV files with election results
  - Any other source data files

### Output Directory (`output/`)
Contains all data generated by the analysis pipeline:

- **`output/processed/`**: Cleaned and processed data files
  - Combined datasets in JSON format
  - Filtered data for Prague 5 specifically
  
- **`output/detailed/`**: Detailed analysis datasets
  - Comprehensive electoral district information
  - Enriched data with additional calculations
  
- **`output/results/`**: Final analysis results
  - Summary statistics and findings
  - Aggregated results by district/party
  
- **`output/visualizations/`**: Generated charts, maps, and dashboards
  - Interactive HTML visualizations
  - Static chart images
  
- **`output/reports/`**: Analysis reports and documentation
  - Comprehensive analysis reports
  - Summary documents in various formats

## Benefits of This Structure

1. **Clear Separation**: Input and output data are clearly separated
2. **Source Control**: Only input data needs to be version controlled
3. **Reproducibility**: Output can be regenerated from input at any time
4. **Data Lineage**: Clear understanding of data flow from source to results
5. **Storage Efficiency**: Output directory can be excluded from backups
6. **Collaboration**: Team members can share input data while generating their own outputs

## Migration Notes

The analysis pipeline has been updated to:
- Read source data from `input/raw/`
- Write all generated data to appropriate `output/` subdirectories
- The legacy `data/` directory can be removed once migration is complete

## Running the Analysis

After the migration, run the analysis as usual:

```bash
python run_analysis.py
```

The pipeline will:
1. Read source data from `input/raw/`
2. Generate processed data in `output/processed/`
3. Create visualizations in `output/visualizations/`
4. Save final results in `output/results/`
5. Generate reports in `output/reports/`
